# 需求：生产稳定性修复与近一周内容再生成

日期：2026-10-06
类型：生产 Bug 修复 / 后台任务治理 / 数据维护
风险：P1
状态：Complete / Fully deployed

## 原始需求

用户要求修复巡检发现的问题，并重新生成近一周的音频和摘要。

## 目标

- 在磁盘耗尽前安全释放空间，并建立有界的音频缓存保留机制。
- 让进入 `error` 的 RSS 源按退避策略自动重试，不再永久退出调度。
- 让 MiniMax 对单条敏感内容的拒绝只影响该条，不拖垮整批翻译。
- 使用用户授权更新的 API Key，并固定生产模型为 `MiniMax-M3`。
- 修复 Digest 列表日期在 Asia/Shanghai 环境下偏移一天的问题。
- 对固定窗口 `2026-09-29T00:00:00+08:00` 至 `2026-10-06T02:40:09+08:00` 的文章重新生成中文摘要与中文音频。
- 保持首页、文章、Feeds、Digest、Broadcast、登录态与历史数据入口兼容。

## 目标用户与触发场景

- 读者：继续获得及时、多来源、带中文摘要和音频的新闻。
- 运维者：磁盘空间有安全余量，失败源会自动恢复，维护任务可分批、可续跑、可审计。
- 触发场景：根分区 100%、57 个源仅 5 个 active、MiniMax 翻译批次多数为 0、近一周内容需要重建。

## 输入与输出

- 输入：现有 PostgreSQL 数据、音频缓存、RSS 状态、MiniMax/TTS 生产配置、固定时间窗 `2026-09-29T00:00:00+08:00` 至 `2026-10-06T02:40:09+08:00`。
- 输出：安全磁盘余量、可恢复的 RSS 调度、隔离后的翻译失败、正确 Digest 日期、近一周重新生成的摘要与音频及可核验统计。

## 调用流程

1. 备份受影响数据库行、Supervisor 配置和清理清单。
2. dry-run 计算音频删除候选；保留 30 天内文件、Broadcast 引用和所有无法确认用途的文件。
3. 应用受控清理，清空指向已删除/已缺失文件的文章音频缓存字段。
4. 部署代码和配置，启动服务并先验证旧入口。
5. 以小批次和 checkpoint 对近一周文章执行摘要、音频再生成。
6. 验证完成数、失败数、磁盘、数据库、日志、页面和 API。
7. 恢复正常 scheduler，观察至少一轮抓取。

UI 布局：N/A。本次不新增或调整页面，只修复后台数据与生产运行行为。

## 边界与非目标

- 不删除文章、用户、收藏、历史、Digest 或 Broadcast 记录。
- 不直接全删音频目录；只有引用核对和 dry-run 后的候选才可清理。
- 不把当前 `main` 上尚未上线的 4 个提交带入 hotfix。
- 不在本次用户授权的 API Key 更新之外继续轮换密钥，不修改模型计费口径。
- 不重构前端 UI，不升级 Next.js 或依赖。
- 不自动生成历史超过近一周的摘要与音频。

## 假设与决策

- “近一周”固定为 `2026-09-29T00:00:00+08:00` 至 `2026-10-06T02:40:09+08:00`，后续续跑不得滑动窗口。
- 音频缓存采用 30 天保留期；更老文章正文仍保留，音频可在未来按需重新生成。
- 生产基线固定为实际运行提交 `6a92017`，通过独立 hotfix 工作区实施。

## 验收标准

- A1（部署）：清理后根分区至少释放 6GiB，且服务无 `ENOSPC` / I/O 错误。
- A2（数据）：不删除文章等业务记录；数据库不再保留指向已删除或已缺失文章音频文件的缓存 URL。
- A3（代码/任务）：音频清理支持 dry-run、30 天保留、引用保护、并发锁和每日一次调度；生产音频目录使用明确的绝对路径。
- A4（集成）：`error` RSS 源按指数退避自动重试，成功后恢复 `active`；调度不会每轮无界重试全部失败源。
- A5（集成）：MiniMax `422 input new_sensitive` 或单条解析失败时，批次被隔离，其他文章仍能翻译。
- A6（API）：`/api/digests`、`/api/digests/latest` 与数据库对同一 `DATE` 返回同一 `YYYY-MM-DD`。
- A7（真实任务）：近一周目标文章完成摘要和中文音频再生成；失败项有 ID、原因和可续跑 checkpoint，不能静默遗漏。
- A8（回归）：首页、文章列表/详情、Feeds、Digest、Broadcast、TTS 音频、匿名鉴权语义和静态资源保持可用。
- A9（性能）：再生成摘要并发不超过 3、音频串行或低并发，单次批量有上限、超时和无进展停止条件。
- A10（安全）：日志和文档不包含 API Key、JWT、cookie；维护入口仅允许有效 ops token，配置权限为 600。
- A11（发布）：生产版本、配置、回滚点、健康检查和发布后日志证据可核验。
- A12（观察）：至少观察一个 scheduler 周期或执行等价的受控失败源重试，确认不会再次永久失活。

## 风险

- 音频删除不可原地恢复，因此先保留 manifest、数据库备份并只删经过引用核验的文件。
- 摘要/TTS 再生成会产生第三方调用成本；通过时间窗、批次、并发和 checkpoint 控制。
- 生产构建空间不足；必须先止血再上传/构建。
- MiniMax 内容安全可能仍拒绝个别文章；验收要求隔离和记录，不承诺绕过内容安全。
