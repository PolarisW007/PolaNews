# PolaNews 项目知识库索引

<!-- POLA_PROJECT_KNOWLEDGE_INDEX_V1 -->

> 本目录集中存放 PolaNews 的产品文档、需求文档、PRD、SDD、架构文档、测试报告、发布记录和开发日志。
> 后续需求和功能改动必须优先读取本目录。

## 推荐阅读顺序

1. `requirements/`：历史需求、当前需求、验收标准。
2. `specs/`：PRD、SDD、交互规格、业务规则。
3. `architecture/`：架构参考、接口、数据流、模块边界。
4. `devlogs/`：开发流水、验证证据、commit 记录。
5. `test-reports/`：测试和回归报告。
6. `release/`：发布记录、回滚方案、部署证据。
7. `analysis/`：性能、调研、专项分析。

## 目录说明

| 目录 | 内容 |
| --- | --- |
| `product/` | 产品功能说明、产品口径、用户价值。 |
| `requirements/` | 用户需求、验收标准、非目标、需求变更记录。 |
| `specs/` | PRD、SDD、功能规格、页面和状态说明。 |
| `architecture/` | 架构文档、接口设计、数据模型、迁移方案。 |
| `release/` | 发布清单、部署记录、回滚方案。 |
| `test-reports/` | 测试报告、回归验证、浏览器验收证据。 |
| `devlogs/` | 开发日志、交付记录、commit 关联。 |
| `analysis/` | 调研分析、性能分析、风险评估。 |

## 维护规则

- 任何代码或配置改动，都必须同步更新需求/PRD/SDD/开发日志中的至少一类记录。
- 中大型需求必须同时有需求记录、PRD、SDD/架构记录和开发日志。
- 小修复可以只更新开发日志，但必须写清楚需求来源、改动原因、验证证据。
- 历史废弃方案必须以 `legacy-` 命名，或在正文开头标注“仅供历史/迁移/风险参考”。
