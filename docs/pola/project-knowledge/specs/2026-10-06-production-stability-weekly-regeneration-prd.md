# PRD：生产稳定性修复与近一周内容再生成

## 产品目标

恢复 PolaNews 的来源覆盖、中文可读性和磁盘安全余量，同时保持既有阅读入口与历史数据不变。

## 用户流程与状态

| 场景 | 系统行为 | 用户可见结果 |
| --- | --- | --- |
| 正常定时抓取 | 抓取 active 与到期可重试的 error 源 | 新文章持续进入首页 |
| RSS 临时失败 | 累计失败、计算下一次退避时间 | 不阻塞其它源；稍后自动恢复 |
| 单条内容被 MiniMax 拒绝 | 拆分批次并隔离失败文章 | 其它文章仍获得中文翻译 |
| 音频过期 | 每日清理超过 30 天且未受保护的缓存 | 最近内容可直接播放，旧内容仍保留正文 |
| 近一周再生成 | 运维入口分批处理并记录进度 | 摘要和音频逐步恢复；失败可续跑 |
| 维护任务中断 | 以数据库结果和 checkpoint 继续 | 不重复无限生成，不丢文章 |
| 维护期禁用 scheduler | 总闸门同时禁止 bootstrap 和 cron 注册 | 再生成期间不会与自动抓取重叠 |

## 异常与降级

- 磁盘清理 dry-run 与实际候选不一致时停止，不删除文件。
- 数据库备份失败时停止清理和再生成。
- MiniMax 单条敏感拒绝只记录文章 ID 和脱敏原因；不记录原文或密钥。
- 第三方 TTS 失败时保留该文章为待生成，不覆盖已有正文。
- 再生成连续两轮无进展时停止，并输出剩余数量，避免无限调用。
- 服务发布失败时恢复 Supervisor 配置和生产基线构建。
- MiniMax endpoint 与 Key 所属区域不一致时停止调用并修正配置；本次生产判定使用 `https://api.minimaxi.com/v1`，不使用返回 `invalid api key` 的 `https://api.minimax.io/v1`。

## 兼容要求

- 页面 URL、公开 API schema、文章 ID、历史 Digest/Broadcast 和鉴权行为保持不变。
- `/api/tts/audio/{filename}` 继续作为音频读取入口。
- 不要求用户重新登录；JWT 配置源在本次只做一致性收口，不轮换 secret。
- 清理不会删除文章、用户数据或历史记录。

## 权限与安全

- 维护型再生成入口使用独立 `POLANEWS_OPS_TOKEN`，未配置返回不可用，错误 token 返回 401。
- token 不进入 URL、响应、日志、文档和 Git。
- 文件清理只能处理受控音频根目录内、满足 UUID MP3 命名规则的文件。

## 验收

验收标准以需求文档 A1-A12 为准。核心产品判断是：服务不仅返回 200，而且来源覆盖、翻译产出、音频空间和近一周内容都恢复到可持续状态。

截至 2026-10-06，本次固定窗口为 `2026-09-29T00:00:00+08:00` 至 `2026-10-06T02:40:09+08:00`；原有 393 篇完成重置和再生成，恢复抓取后又有 2 篇新增文章因 `published_at` 落入同一窗口而自动处理，最终摘要与音频覆盖均为 395/395，pending=0、失败=0。Scheduler bootstrap 已完整结束，真实 `422 new_sensitive` 完成单篇隔离，feed 失败/恢复 canary 通过且无残留；产品验收完成。
